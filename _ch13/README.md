# 13. 쓰레드 (Thread)

## 💡 주요 개념 정리

### 1. 프로세스(Process)와 쓰레드(Thread)
- **프로세스 (Process)**:
  - **정의**: OS로부터 필요한 메모리와 자원을 할당받아 실행 중인 프로그램을 의미합니다.
  - **구성**: 데이터, 메모리 등의 자원과 쓰레드로 구성됩니다.
- **쓰레드 (Thread)**:
  - **정의**: 프로세스 내에서 실제로 작업을 실행하는 최소 작업 단위입니다.
  - **구조**: 모든 프로세스는 최소 하나 이상의 쓰레드(Main Thread)를 가지며, 둘 이상의 쓰레드를 지닌 프로세스를 **멀티쓰레드 프로세스(Multi-threaded Process)**라고 합니다.
- **멀티프로세싱 vs 멀티쓰레딩**:
  - 멀티프로세스는 각 프로세스가 독립적인 메모리 영역을 가져 안전하지만 자원 소모가 크고 프로세스 간 통신(IPC)이 복잡합니다.
  - 멀티쓰레드는 하나의 프로세스 내부에서 **호출 스택(Call Stack)만 분리**하고 코드(Code), 데이터(Data), 힙(Heap) 메모리 영역을 공유하므로 시스템 자원이 효율적으로 절약되며 데이터 교환이 빠릅니다. 단, 여러 쓰레드가 자원에 동시 접근할 때 동기화(Synchronization) 제어가 필수적입니다.

### 2. 쓰레드의 구현 방법 2가지
자바에서 쓰레드를 생성하는 방법은 표준적으로 2가지가 존재합니다.

1. **`Thread` 클래스 상속**
   - 선언 방법: `class MyThread extends Thread`
   - 작업 내용 기술: `run()` 메서드를 오버라이딩합니다.
   - 쓰레드 이름 조회: 조상 클래스의 메서드인 `getName()`을 바로 호출하여 쓰레드명을 획득합니다.
   - 단점: 자바는 단일 상속만 허용하므로, 다른 클래스를 상속받아야 하는 경우 다중 상속이 불가능해 설계적 유연성이 저하됩니다.

2. **`Runnable` 인터페이스 구현 (권장)**
   - 선언 방법: `class MyThread implements Runnable`
   - 작업 내용 기술: 추상 메서드인 `run()`을 구현합니다.
   - 쓰레드 이름 조회: `Thread.currentThread().getName()`을 이용해 현재 돌고 있는 쓰레드 참조객체를 구한 뒤 호출해야 합니다.
   - 장점: 다른 클래스를 상속받을 수 있는 확장성을 보장하므로 객체지향적인 재사용성이 우수합니다.
   - 실행 구조: 구현체 자체는 쓰레드가 아니므로, `new Thread(Runnable target)`과 같이 `Thread` 생성자에 인자로 전달하여 조립한 후 실행해야 합니다.

### 3. start()와 run()의 근원적 차이
- **`run()`의 작동 방식**:
  - 쓰레드 객체 내에 오버라이딩된 일반 메서드 `run()`을 단순 호출하는 것입니다.
  - 새로운 쓰레드가 분기되지 않으며, 코드를 호출한 현재 쓰레드(예: main 쓰레드)의 기존 호출 스택(Call Stack) 내부에서 동기적으로 코드가 처리됩니다.
- **`start()`의 작동 방식**:
  - JVM에게 새로운 쓰레드 생성을 요청합니다.
  - JVM은 메모리에 독립적인 **새로운 호출 스택(Call Stack)**을 확보(할당)합니다.
  - 새로 할당된 독립 스택 최하단에 `run()` 메서드를 배치시키고 쓰레드를 실행 대기 상태로 등록하여 **비동기 멀티쓰레딩** 작업을 착수시킵니다.

```
[ 일반 run() 호출 ]           [ start() 호출을 통한 멀티쓰레딩 ]
┌──────────────┐             ┌──────────────┐  ┌──────────────┐
│    run()     │             │    main()    │  │    run()     │
├──────────────┤             ├──────────────┤  ├──────────────┤
│    main()    │             │  (호출스택A) │  │  (호출스택B) │
└──────────────┘             └──────────────┘  └──────────────┘
(단일 스택에서 동기 처리)      (물리적으로 격리된 스택에서 병행 처리)
```

### 4. OS 스케줄러(OS Scheduler)와 실행 지연
- 쓰레드 인스턴스에 `start()`를 호출하더라도 해당 쓰레드가 즉시 실행 상태가 되는 것은 아닙니다. 실행 대기(Runnable) 상태에서 **OS의 쓰레드 스케줄러(Thread Scheduler)**에 의해 CPU 할당 권한을 배정받아야 실행됩니다.
- 스케줄러는 쓰레드 우선순위, 대기 시간 등을 복합적으로 고려하여 작업을 컨텍스트 스위칭(Context Switching)해가며 시분할 처리합니다. 이 동작은 OS 커널에 의존적이므로 실행 순서나 할당 시간은 매 실행 시마다 비결정론적으로 달라집니다.

### 5. 싱글쓰레드와 멀티쓰레드의 효율성 비교
- **컨텍스트 스위칭 (Context Switching) 오버헤드**:
  - 싱글쓰레드로 두 작업을 차례대로 순차 진행하는 것(`Ex13_03`)과, 멀티쓰레드를 사용해 두 작업을 번갈아가며 병행 처리하는 것(`Ex13_04`)을 비교하면 총 작업 소요시간은 대개 **싱글쓰레드가 미세하게 더 빠릅니다.**
  - 이는 쓰레드가 교체될 때 현재 진행 중인 상태 정보를 레지스터 및 메모리에 백업하고, 교체되어 들어오는 쓰레드의 상태를 복구하는 **컨텍스트 스위칭 비용** 및 화면 출력과 같은 공유 I/O 스트림 경쟁에 따른 대기 연산 때문입니다.
  - **사용 이유**: 성능상 미세한 손실이 있음에도 멀티쓰레드를 쓰는 이유는, 여러 작업을 동시 다발적으로 처리함으로써 프로그램 전체의 **사용자 반응성(Responsiveness)**을 높이고 컴퓨터 자원을 효율적으로 대기 없이 쓸 수 있기 때문입니다.

### 6. 쓰레드의 우선순위 (Priority)
- 자바 쓰레드는 작업을 배정받는 빈도 조절을 위해 우선순위(Priority)를 1부터 10까지 정수 수준으로 지정할 수 있습니다. (디폴트는 5).
- `setPriority(int priority)`와 `getPriority()` 메서드로 제어하며, 가독성을 위해 Thread 클래스에 내장된 상수들을 사용할 수 있습니다.
  - `Thread.MAX_PRIORITY`: 우선순위 10 (가장 높음)
  - `Thread.NORM_PRIORITY`: 우선순위 5 (보통, 기본값)
  - `Thread.MIN_PRIORITY`: 우선순위 1 (가장 낮음)
- 이론적으로 높은 우선순위를 지닌 쓰레드가 CPU 연산 시간을 더 많이 할당받아야 하나, 실제로는 가벼운 실습 레벨에서는 OS 스케줄러 정책에 영향을 크게 받아 항상 비결정론적인 임의성을 띱니다.

### 7. 쓰레드의 작업 조율과 일시정지 (join())
- **정의**: 특정 쓰레드가 작업을 종료할 때까지, 메서드를 호출한 현재 쓰레드(예: main 쓰레드)를 **일시정지 상태(Waiting)**로 대기하게 만드는 동기화 헬퍼 메서드입니다.
- **예외 처리 필수**: `join()`은 대상 쓰레드가 끝나기 전에 인터럽트 신호를 받으면 깨어날 수 있으므로 반드시 `try-catch` 블록으로 둘러싸 `InterruptedException` 예외를 처리해주어야 합니다.
- **사용 사례**: 병렬로 쪼갠 작업들이 전부 완료된 뒤 결과를 합산하거나, 특정 쓰레드들의 종료 시점을 결합해 총 작업 소요 시간을 정밀 측정하고자 할 때 유용하게 쓰입니다.

### 8. 메인 쓰레드 (Main Thread)
- **정의**: 자바 애플리케이션 실행 시 JVM이 가장 먼저 구동시키는 최초의 실행 흐름입니다. `main` 메서드의 시작부터 순차적으로 코드를 실행해 나갑니다.
- **생명주기 관계**:
  - 싱글쓰레드 환경에서는 메인 쓰레드가 종료되면 프로그램도 즉시 종료됩니다.
  - 멀티쓰레드 환경에서는 메인 쓰레드가 종료되더라도, 실행 중인 **일반 사용자 쓰레드(User Thread)**가 단 하나라도 남아있다면 프로그램은 완전히 종료되지 않고 유지됩니다. (단, 백그라운드 보조 역할을 수행하는 데몬 쓰레드는 프로그램 종료를 저지하지 못합니다.)

### 9. 쓰레드와 I/O 블락킹 (I/O Blocking)
- **개념**: 쓰레드가 키보드 입력 대기, 파일 읽기/쓰기, 네트워크 패킷 수신 등 입출력(I/O) 작업을 수행할 때, 해당 I/O 작업이 완료될 때까지 쓰레드가 CPU 제어권을 반납하고 대기(Blocked) 상태로 멈추는 현상입니다.
- **싱글쓰레드 환경에서의 문제점**: I/O 블락킹이 일어나는 동안 CPU가 아무런 일도 하지 못하고 통째로 쉬기 때문에 자원 낭비가 매우 크고, 사용자 입력 대기 중에는 다른 연산이나 화면 렌더링이 완전히 멈춰 반응성이 마비됩니다.
- **멀티쓰레드 환경에서의 해결**: 한 쓰레드가 사용자 입력을 대기하느라 블락킹 상태에 빠지더라도, OS 스케줄러가 대기 상태인 쓰레드를 비우고 실행 가능한 다른 작업 쓰레드에 CPU 제어권을 배정하므로 프로그램 전체가 중단되지 않고 안정적으로 화면 반응성을 유지하며 백그라운드 연산을 병행 처리할 수 있습니다.

### 10. 쓰레드 그룹 (Thread Group)
- **정의**: 서로 관련된 쓰레드를 묶어서 디렉토리 계층 구조처럼 논리적으로 묶어 관리할 수 있도록 제공하는 자바 내장 개념입니다. (`ThreadGroup` 클래스로 제어).
- **특징 및 룰**:
  - 모든 쓰레드는 반드시 단 하나의 쓰레드 그룹에 소속됩니다. 쓰레드 생성 시 그룹을 지정하지 않으면, 그 쓰레드를 생성한 조상 쓰레드가 소속된 그룹(기본적으로 `main` 그룹)에 자동으로 속하게 됩니다.
  - **보안 및 관리 경계**: 하나의 쓰레드는 자신이 속한 쓰레드 그룹 외에 다른 쓰레드 그룹의 쓰레드를 임의로 제어하거나 속성을 조작할 수 없도록 격리 보안 제한이 걸립니다.
  - **일괄 관리 기능**: 특정 쓰레드 그룹의 모든 쓰레드에 한 번에 인터럽트(`interrupt()`) 신호를 뿌리거나, 쓰레드 그룹 내의 예외 미처리 흐름을 중앙 제어하는 `uncaughtException()` 구현 등을 통해 멀티쓰레드를 그룹 단위로 유연하게 일괄 제어할 수 있습니다.

### 11. 쓰레드 관련 주요 메서드 요약
자바 쓰레드를 상태 제어하고 속성을 설정할 때 사용하는 API 일람입니다.

| 메서드명 | 설명 | 비고 |
| :--- | :--- | :--- |
| `start()` | 쓰레드의 실행을 시작시킴 (독립 호출 스택 할당) | 신규 쓰레드 분기 시작 |
| `run()` | 쓰레드가 실행할 작업 코드가 선언된 바디 | 직접 호출 시 단순 메서드 실행 |
| `join()` / `join(long ms)` | 대상 쓰레드가 작업을 종료할 때까지 대기 | `InterruptedException` 예외 처리 필수 |
| `sleep(long ms)` | 지정된 시간 동안 현재 실행 중인 쓰레드를 일시정지 | static 메서드 (실행 쓰레드 대상) |
| `interrupt()` | 일시정지 상태인 쓰레드에 예외를 강제 주입해 깨움 | 인터럽트 상태 변경 (`false` -> `true`) |
| `isInterrupted()` | 쓰레드의 인터럽트 상태를 조회 | 플래그 상태 변화 없음 |
| `Thread.interrupted()` | 현재 실행 중인 쓰레드의 인터럽트 플래그를 조회 | 플래그를 `false`로 자동 초기화 |
| `Thread.yield()` | 자신에게 할당된 CPU 실행 시간을 다른 대기 쓰레드에 양보 | 즉시 실행 대기(Runnable) 상태로 이동 |
| `Thread.currentThread()` | 현재 이 코드를 실행 중인 쓰레드의 참조를 획득 | static 메서드 |
| `isAlive()` | 쓰레드가 가동되어(`start`) 종료되기 전까지의 생존 여부 반환 | `boolean` 값 반환 |
| `setDaemon(boolean on)` | 쓰레드를 데몬 쓰레드 혹은 일반 쓰레드로 지정 | `start()` 호출 이전에만 설정 가능 |
| `setPriority(int priority)` | 쓰레드의 실행 우선순위(1~10) 부여 | 디폴트값은 `NORM_PRIORITY` (5) |
| `suspend()` | 쓰레드의 실행을 일시정지시킴 | **Deprecated** (교착상태 유발) |
| `resume()` | 일시정지된 쓰레드의 실행을 다시 재개시킴 | **Deprecated** (교착상태 연동) |
| `stop()` | 실행 중인 쓰레드를 즉각 완전 종료시킴 | **Deprecated** (데이터 불일치 유발) |

### 12. 쓰레드의 양보 (yield())
- **정의**: 실행 중인 쓰레드가 자신에게 할당된 시분할 CPU 시간(Time slice)을 남겨둔 채, 다른 대기 상태인 동등한 우선순위의 쓰레드에게 **실행 제어권을 즉시 양보**하고 자신은 실행 대기(Runnable) 상태로 돌아가는 기능입니다.
- **동작 원리**:
  - `yield()`와 `sleep(ms)`의 차이는, `sleep`은 지정된 밀리초 동안 대기 상태(Waiting)로 완전히 빠져 잠들지만, `yield`는 일시정지 대기 상태가 되지 않고 곧장 **실행 대기(Runnable) 큐**로 들어가 스케줄러의 다음 배정을 즉각 준비한다는 점입니다.
  - **효율적인 바쁜 대기(Busy-Waiting) 방지**: 무의미한 조건 대기 반복 루프(`while(true)`) 안에서 조건이 풀리기를 계속 체크하면서 CPU 연산력을 과소비(Busy-waiting)하는 대신, 조건 충족이 안 될 시 `Thread.yield()`를 호출해주면 즉시 CPU를 다른 가치 있는 쓰레드에 인계하므로 프로그램 실행 효율이 극적으로 상승합니다.

### 13. 구버전 쓰레드 제어 메서드의 감가(Deprecated)와 교착상태(Deadlock)
자바 초기에는 쓰레드의 상태를 임의로 직접 제어할 수 있는 직관적인 메서드들이 제공되었으나, 현재는 사용이 엄격히 제한(Deprecated)되었습니다.

- **`suspend()` (일시정지), `resume()` (재개), `stop()` (강제 종료)**:
  - **기능**: 실행 중인 쓰레드를 임의로 재우거나 다시 깨우고, 강제로 폭사시키는 아주 즉각적인 형태의 제어 명령이었습니다.
  - **감가(Deprecated) 처리된 원인**:
    - **`suspend()`의 교착상태(Deadlock) 유발**: 쓰레드가 일시정지될 때, 자신이 획득해서 선점하고 있던 **공유 자원의 락(Lock)을 해제하지 않고 손에 쥔 채로** 일시정지 상태에 빠집니다. 이 자원을 확보해서 쓰레드를 다시 깨워줘야 할 다른 실행 쓰레드가 해당 자원 락에 접근하지 못해 블락되면서, 서로를 마냥 기다리며 프로그램이 완전히 마비되는 교착상태(Deadlock)를 초래합니다.
    - **`stop()`의 데이터 무결성 훼손**: 쓰레드가 한창 임계 영역 내부에서 자원을 가공/처리하고 있는 와중에 외부에서 강제로 즉각 소멸당하게 되면, 공유 객체가 정합성이나 정리가 덜 된 불안정한 상태에서 강제로 락이 풀려 버립니다. 이로 인해 공유 데이터가 물리적으로 훼손되거나 비정상적인 상태로 노출되는 동기화 유실(Thread-unsafe) 문제가 일어납니다.
  - **권장되는 대안**:
    - 외부에서 플래그 변수(예: `boolean suspended`, `boolean stopped`)를 필드로 제공하고, `run()` 루프문 내에서 이 변수의 조건을 수시로 분기 검사하도록 코드를 설계하여 쓰레드가 스스로 질서 있게 실행 흐름을 멈추거나 빠져나가도록 유도하는 것이 표준 가이드라인입니다.

### 10. [Ex13_10.java](./src/Ex13_10.java) - 멀티쓰레드 환경에서의 데이터 동기화 (synchronized)
- 멀티쓰레드 환경에서 여러 쓰레드가 공통된 자원(여기서는 `Account` 인스턴스의 잔고 `balance`)에 동시에 접근할 때 발생할 수 있는 동시성 문제(Race Condition)를 학습합니다.
- 메서드 선언부에 `synchronized` 키워드를 부여하여, 특정 쓰레드가 출금 작업(`withdraw()`)을 수행하는 동안 다른 쓰레드가 진입하지 못하도록 락(Lock)을 걸어 데이터의 무결성을 보장하는 구조를 실습합니다.

```java
public synchronized void withdraw(int money) {
    if (balance >= money) {
        try { Thread.sleep(1000); } catch(InterruptedException e) {}
        balance -= money;
    }
}
```
