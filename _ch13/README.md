# 13. 쓰레드 (Thread)

## 💡 주요 개념 정리

### 1. 프로세스(Process)와 쓰레드(Thread)
- **프로세스 (Process)**:
  - **정의**: OS로부터 필요한 메모리와 자원을 할당받아 실행 중인 프로그램을 의미합니다.
  - **구성**: 데이터, 메모리 등의 자원과 쓰레드로 구성됩니다.
- **쓰레드 (Thread)**:
  - **정의**: 프로세스 내에서 실제로 작업을 실행하는 최소 작업 단위입니다.
  - **구조**: 모든 프로세스는 최소 하나 이상의 쓰레드(Main Thread)를 가지며, 둘 이상의 쓰레드를 지닌 프로세스를 **멀티쓰레드 프로세스(Multi-threaded Process)**라고 합니다.
- **멀티프로세싱 vs 멀티쓰레딩**:
  - 멀티프로세스는 각 프로세스가 독립적인 메모리 영역을 가져 안전하지만 자원 소모가 크고 프로세스 간 통신(IPC)이 복잡합니다.
  - 멀티쓰레드는 하나의 프로세스 내부에서 **호출 스택(Call Stack)만 분리**하고 코드(Code), 데이터(Data), 힙(Heap) 메모리 영역을 공유하므로 시스템 자원이 효율적으로 절약되며 데이터 교환이 빠릅니다. 단, 여러 쓰레드가 자원에 동시 접근할 때 동기화(Synchronization) 제어가 필수적입니다.

### 2. 쓰레드의 구현 방법 2가지
자바에서 쓰레드를 생성하는 방법은 표준적으로 2가지가 존재합니다.

1. **`Thread` 클래스 상속**
   - 선언 방법: `class MyThread extends Thread`
   - 작업 내용 기술: `run()` 메서드를 오버라이딩합니다.
   - 쓰레드 이름 조회: 조상 클래스의 메서드인 `getName()`을 바로 호출하여 쓰레드명을 획득합니다.
   - 단점: 자바는 단일 상속만 허용하므로, 다른 클래스를 상속받아야 하는 경우 다중 상속이 불가능해 설계적 유연성이 저하됩니다.

2. **`Runnable` 인터페이스 구현 (권장)**
   - 선언 방법: `class MyThread implements Runnable`
   - 작업 내용 기술: 추상 메서드인 `run()`을 구현합니다.
   - 쓰레드 이름 조회: `Thread.currentThread().getName()`을 이용해 현재 돌고 있는 쓰레드 참조객체를 구한 뒤 호출해야 합니다.
   - 장점: 다른 클래스를 상속받을 수 있는 확장성을 보장하므로 객체지향적인 재사용성이 우수합니다.
   - 실행 구조: 구현체 자체는 쓰레드가 아니므로, `new Thread(Runnable target)`과 같이 `Thread` 생성자에 인자로 전달하여 조립한 후 실행해야 합니다.

### 3. start()와 run()의 근원적 차이
- **`run()`의 작동 방식**:
  - 쓰레드 객체 내에 오버라이딩된 일반 메서드 `run()`을 단순 호출하는 것입니다.
  - 새로운 쓰레드가 분기되지 않으며, 코드를 호출한 현재 쓰레드(예: main 쓰레드)의 기존 호출 스택(Call Stack) 내부에서 동기적으로 코드가 처리됩니다.
- **`start()`의 작동 방식**:
  - JVM에게 새로운 쓰레드 생성을 요청합니다.
  - JVM은 메모리에 독립적인 **새로운 호출 스택(Call Stack)**을 확보(할당)합니다.
  - 새로 할당된 독립 스택 최하단에 `run()` 메서드를 배치시키고 쓰레드를 실행 대기 상태로 등록하여 **비동기 멀티쓰레딩** 작업을 착수시킵니다.

```
[ 일반 run() 호출 ]           [ start() 호출을 통한 멀티쓰레딩 ]
┌──────────────┐             ┌──────────────┐  ┌──────────────┐
│    run()     │             │    main()    │  │    run()     │
├──────────────┤             ├──────────────┤  ├──────────────┤
│    main()    │             │  (호출스택A) │  │  (호출스택B) │
└──────────────┘             └──────────────┘  └──────────────┘
(단일 스택에서 동기 처리)      (물리적으로 격리된 스택에서 병행 처리)
```

### 4. OS 스케줄러(OS Scheduler)와 실행 지연
- 쓰레드 인스턴스에 `start()`를 호출하더라도 해당 쓰레드가 즉시 실행 상태가 되는 것은 아닙니다. 실행 대기(Runnable) 상태에서 **OS의 쓰레드 스케줄러(Thread Scheduler)**에 의해 CPU 할당 권한을 배정받아야 실행됩니다.
- 스케줄러는 쓰레드 우선순위, 대기 시간 등을 복합적으로 고려하여 작업을 컨텍스트 스위칭(Context Switching)해가며 시분할 처리합니다. 이 동작은 OS 커널에 의존적이므로 실행 순서나 할당 시간은 매 실행 시마다 비결정론적으로 달라집니다.

### 5. 싱글쓰레드와 멀티쓰레드의 효율성 비교
- **컨텍스트 스위칭 (Context Switching) 오버헤드**:
  - 싱글쓰레드로 두 작업을 차례대로 순차 진행하는 것(`Ex13_03`)과, 멀티쓰레드를 사용해 두 작업을 번갈아가며 병행 처리하는 것(`Ex13_04`)을 비교하면 총 작업 소요시간은 대개 **싱글쓰레드가 미세하게 더 빠릅니다.**
  - 이는 쓰레드가 교체될 때 현재 진행 중인 상태 정보를 레지스터 및 메모리에 백업하고, 교체되어 들어오는 쓰레드의 상태를 복구하는 **컨텍스트 스위칭 비용** 및 화면 출력과 같은 공유 I/O 스트림 경쟁에 따른 대기 연산 때문입니다.
  - **사용 이유**: 성능상 미세한 손실이 있음에도 멀티쓰레드를 쓰는 이유는, 여러 작업을 동시 다발적으로 처리함으로써 프로그램 전체의 **사용자 반응성(Responsiveness)**을 높이고 컴퓨터 자원을 효율적으로 대기 없이 쓸 수 있기 때문입니다.

### 6. 쓰레드의 우선순위 (Priority)
- 자바 쓰레드는 작업을 배정받는 빈도 조절을 위해 우선순위(Priority)를 1부터 10까지 정수 수준으로 지정할 수 있습니다. (디폴트는 5).
- `setPriority(int priority)`와 `getPriority()` 메서드로 제어합니다.
- 이론적으로 높은 우선순위를 지닌 쓰레드가 CPU 연산 시간을 더 많이 할당받아야 하나, 실제로는 가벼운 실습 레벨에서는 OS 스케줄러 정책에 영향을 크게 받아 항상 비결정론적인 임의성을 띱니다.

### 7. 쓰레드의 작업 조율과 일시정지 (join())
- **정의**: 특정 쓰레드가 작업을 종료할 때까지, 메서드를 호출한 현재 쓰레드(예: main 쓰레드)를 **일시정지 상태(Waiting)**로 대기하게 만드는 동기화 헬퍼 메서드입니다.
- **예외 처리 필수**: `join()`은 대상 쓰레드가 끝나기 전에 인터럽트 신호를 받으면 깨어날 수 있으므로 반드시 `try-catch` 블록으로 둘러싸 `InterruptedException` 예외를 처리해주어야 합니다.
- **사용 사례**: 병렬로 쪼갠 작업들이 전부 완료된 뒤 결과를 합산하거나, 특정 쓰레드들의 종료 시점을 결합해 총 작업 소요 시간을 정밀 측정하고자 할 때 유용하게 쓰입니다.

### 1. [Ex13_01.java](./src/Ex13_01.java) - 두 가지 쓰레드 구현 및 실행 실습
- `Thread` 클래스를 상속한 `ThreadEx1_1`과 `Runnable` 인터페이스를 구현한 `ThreadEx1_2`를 작성하여 멀티쓰레드를 구성합니다.
- 메인 메서드에서 `start()`를 호출해 각 쓰레드를 구동하며, 실행 순서가 매번 보장되지 않고 OS 스케줄러에 따라 엇갈려 실행되는 모습을 관찰합니다.

```java
// 1. Thread 상속 방식
ThreadEx1_1 t1 = new ThreadEx1_1();

// 2. Runnable 구현 방식 (생성자 주입 방식)
Runnable r = new ThreadEx1_2();
Thread t2 = new Thread(r);

t1.start(); // 호출 스택 할당 및 비동기 독립 실행 시작
t2.start();
```

### 2. [Ex13_02.java](./src/Ex13_02.java) - join()을 이용한 쓰레드 조율 및 실행 제어
- 두 개의 쓰레드(`ThreadEx2_1`, `ThreadEx2_2`)를 구동하고, `th1.join()`, `th2.join()` 명령어를 호출하여 두 쓰레드의 작업이 완전히 완료될 때까지 main 쓰레드가 대기하도록 조정합니다.
- 동기적 대기를 통해 멀티쓰레드로 구동한 두 작업의 전체 소요 시간을 정밀하게 산정하는 방법을 실습합니다.

```java
th1.start();
th2.start();
try {
    th1.join(); // th1 종료 시까지 main 쓰레드가 대기
    th2.join(); // th2 종료 시까지 main 쓰레드가 대기
} catch (InterruptedException e) {}
```

### 4. [Ex13_04.java](./src/Ex13_04.java) - 멀티쓰레드 병행 처리와 컨텍스트 스위칭
- 하나의 서브 쓰레드(`ThreadEx3_1`)와 메인 쓰레드가 각각 `-` 와 `|` 의 출력을 독립적으로 교차 실행하게 만듭니다.
- `Ex13_03`의 싱글쓰레드 결과와 소요 시간을 실측 대조하며, 쓰레드 간의 잦은 **컨텍스트 스위칭 비용(Context Switching Overhead)** 및 자원 경쟁으로 인해 미세하게 시간이 더 걸리는 원리를 학습합니다.

```java
ThreadEx3_1 th1 = new ThreadEx3_1();
th1.start(); // 백그라운드에서 '|' 출력 쓰레드 가동

for (int i = 0 ; i<300 ; i++)
    System.out.printf("%s",new String("-")); // 메인에서 '-' 출력
```

### 5. [Ex13_05.java](./src/Ex13_05.java) - 쓰레드 스케줄링 및 우선순위 제어
- 쓰레드 인스턴스에 우선순위(`setPriority()`)를 5와 7로 각각 다르게 부여하여 실행 결과를 관찰합니다.
- 자바 가상머신과 OS의 스레드 스케줄러 간의 상호작용을 파악하고, 높은 우선순위의 쓰레드가 더 자주 CPU 시간을 선점하도록 배정되는 기법을 실습합니다.

```java
th1.setPriority(5);
th2.setPriority(7);
th1.start();
th2.start();
```
